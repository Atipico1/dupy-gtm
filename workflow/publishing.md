# 예약·게시·댓글 DM 계약

사용자가 선택한 최신 파일과 현재 요청을 기준으로 한다. 연결 서비스의 도구를 우선 사용하며, 실제 계정 키·예약 ID·캡션·DM 본문·영수증은 비공개 실행 폴더에 둔다.

## 예약 전

1. 최신 선택본의 경로·SHA-256·크기·재생 길이·세로 화면비와 변경 검수 기록을 확인한다. 같은 번호의 이전 렌더를 올리지 않는다.
2. 현재 연결 프로필의 사용자 이름을 새로 조회한다. 계정 키나 오래된 별칭만으로 게시 대상을 판단하지 않는다.
3. 오늘·내일을 사용자 시간대의 절대 날짜와 KST 시각으로 바꾸고 UTC 값도 대조한다. 기존 대기열에서 같은 파일·대상·시각의 중복 예약을 확인한다.
4. 승인된 캡션·CTA·DM 설정을 재사용한다. 실제 요청에 맞춰 문안을 작성할 권한이 있으면 영상 내용과 맞게 작성한다. 키워드/모든 댓글, 팔로우 조건, 공개 답글, 링크 목적지는 각각 별도 설정이다.
5. 검수 한계를 전달받은 사용자가 해당 결과물의 게시를 명시적으로 선택하면 그 지시와 미해결 항목을 함께 기록한다. 사용자 선택을 기술적 전체 PASS로 바꾸지 않는다. 계정·파일·시각 불명확 같은 운영 오류는 먼저 해소한다.

## 업로드와 예약 확정

- 요청 전에 파일 해시와 예약 의도를 기록한다. 생성된 예약 ID를 바로 보존하고 업로드는 그 항목에 연결한다.
- 로컬 파일 예약의 `draft`는 파일 대기 상태다. 서명된 URL로 업로드한 뒤 서버의 파일 검사와 `scheduled` 상태를 다시 읽어야 예약 완료다.
- 업로드가 실패하면 예약 상태와 응답 본문을 먼저 확인한다. 새 예약을 만들지 말고 기존 ID의 업로드를 복구한다. 전송 도구 문제라면 서비스가 안내하는 업로드 방법을 사용할 수 있다. 만료된 주소는 정상 재발급 도구를 쓰며 인증·접근 제한을 우회하지 않는다.
- 서명된 업로드 URL은 일시적인 권한이다. 로그·공개 문서·Git에 남기지 않는다. 다른 연동이 쓰는 인증 토큰을 임의 교체하지 않는다.
- 업로드 후 계정, 파일 이름·크기·길이·화면비, 캡션, 절대 예약 시각, DM 설정을 요청값과 비교한다. 예약 실행기가 동작하는지 확인하고 서버 상태·확인 시각을 영수증에 남긴다.

## 완료 상태를 구분하기

| 상태 | 확인할 근거 |
|---|---|
| 예약 등록 | 파일 업로드·서버 검사 완료, 정확한 시각으로 `scheduled` 재조회 |
| 게시 완료 | 게시 결과와 실제 공개 permalink의 대상·문안·영상 확인 |
| DM 규칙 연결 | 예약에 첨부되었는지, 게시 후 규칙이 활성화됐는지 각각 확인 |
| DM 수신 확인 | 승인된 테스트 또는 실제 전송 영수증. 규칙 저장만으로 수신 성공을 주장하지 않음 |

최종 응답에는 대상 계정과 절대 KST 일정을 적고 예약 관리 화면 또는 비공개 영수증 링크를 제공한다. 아직 시간이 오지 않은 예약을 게시 완료라고 보고하지 않는다. 예약 조회가 불명확하면 중복 발행하지 않고 기존 ID로 복구한다.
