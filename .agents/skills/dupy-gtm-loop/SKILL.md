# Dupy GTM loop

프로젝트 루트는 이 스킬을 제공하는 저장소다. 먼저 `workflow/config.json`, `workflow/dupy-gtm-loop.md`, `research/dupy-product-sot.md`를 읽는다. Harness² 설계 근거가 필요한 경우 `research/harness2-analysis.md`를 읽는다. 현재 사용자의 실행/중지 범위를 확인한다. 실행마다 `workflow/run-records.md`를 읽고 새 시간 기반 run 폴더를 만들며, 기존 회차를 이어가면 source_runs로 연결한다.

실행 모드는 config와 해당 회차의 activation을 읽어 판정한다. 설계·스킬 수정 요청을 제작·게시 실행으로 해석하지 않는다. 사용자가 실행을 명시하고 자산/예산/계정 범위가 정해지면 그 회차에서 리뷰 통과 후 게시까지 진행한다. 중지되거나 선택되지 않은 테스트 결과를 새 회차의 승인된 자산으로 자동 채택하지 않는다.

## 한 회차

1. 연결된 인앱 브라우저에서 @dupy.app Instagram/Threads의 자기 게시물 성과를 읽는다. 계정 확인 후 원문 URL·관측시간·화면 증거와 실제 지표를 저장한다. 보이지 않는 값은 null. 새 계정이면 콜드스타트로 명시한다.
2. 등록된 채널만 TikHub CLI로 수집한다. `tikhub <platform> --help`와 endpoint help를 먼저 확인한다. 저장된 JSON/48시간 캐시를 재사용한다. 필요한 신선도에 따라 max-age를 지정하고 무조건 no-cache로 호출하지 않는다. API payload와 pagination을 검사한다. Threads username 경로가 실패하면 공식 CLI의 ID 경로를 확인하되 실패 요청을 맹목 반복하지 않는다. `calls.jsonl`의 api_call과 cache_hit을 구분한다.
3. 사용자 지정 레퍼런스의 훅 문구·첫 화면·표정/행동·자막·박자를 `locked_reference_hook`으로 고정한다. 훅이 제품과 직접 관련 없어도 제품형 훅으로 고치거나 새 후보를 제안하지 않는다. 제품명·쇼핑쇼츠·차별점은 훅 다음 설명/데모/결과에만 반영한다. 기획 후보가 필요하면 같은 훅 아래 설명부 구성을 비교하고 원본 URL/타임코드·Dupy 사용 장면·CTA·치환 매핑을 남긴다. 사용자가 훅 변경을 명시한 경우에만 고정을 해제한다.
4. 독립된 리뷰 역할이 고정 훅을 원문/원본 프레임과 먼저 대조하고, 설명부를 SoT·실제 데모와 대조해 적격 후보 중1개를 선택한다. 훅 임의 교체·제품 키워드 삽입은 제작 전 수정한다. 구체적 이유를 남기며 최대2회 수정 후 미해결이면 멈춘다.
5. 선택안에만 OpenRouter의 `tts-reference-clone-model`로 음성 생성 모델 전용 음성을 만들고 확인한 뒤, 영상 생성 모델 reference-to-video에 원본 구간+전용 인물 사진+배경 사진+음성 생성 모델 음성을 넣는다. 전체 영상 제작에 필요한 사진/고정 음성 자산/예산 누락이면 실행하지 않는다. 음성만 요청한 경우에는 사진이나 영상 기획을 요구하지 않고 고정 음성·대사·해당 실행 범위만 확인한다. 최신 모델 규격·가격 확인, job ID 보존, 결과 불명 유료요청 재제출 금지. 입력별 역할과 실제 발화 타이밍을 확인하고 실제 Dupy UI와 자막을 조립한다.
6. 별도 리뷰 역할이 최종 영상을 처음부터 끝까지 시청·청취하고 채널별 문안·CTA 목적지·대상계정도 검수한다. 검수한 파일/문안 해시와 계정 ID를 content-review.json에 기록한다. 프레임만 확인했으면 전체 리뷰 미완료다. 훅/주장/제품UI/인물/손/립싱크/끝어미/자막/CTA를 타임코드로 평가한다. 충돌하는 검수는 UNKNOWN, 오류는 REVISE. 최대2회 수정 후 미해결이면 중지한다. 작은 부분 수정은 변경 구간과 연결부를 독립 검수하고 기존 미해결 항목을 유지한다.
7. 허용된 회차에서 검수 파일·문안·대상계정과 사용자 선택이 동일한지 확인하고 `workflow/publishing.md`에 따라 게시 또는 예약한다. 검수 한계를 알고 선택한 사용자 지시는 별도 기록하며 전체 PASS로 바꾸지 않는다. 원문 permalink를 다시 열어 영수증에 기록한다. 게시 성공 불명확시 재게시하지 말고 피드를 대조한다. 이후24/72/168시간 성과를 다음 회차 입력으로 예약할 수 있으나 실제 자동화 도구로 생성·검증하기 전 예약됐다고 하지 않는다.

## 실행 구조

성과 분석자, 시장 분석자, 기획자, 기획 리뷰어, 제작자, 콘텐츠 리뷰어, 게시자 역할을 분리한다. 동시 작업은1·2단계에만 필요하며 자산/상태파일은 회차별로 분리한다. 오케스트레이터가 상태 전이를 소유하고 리뷰어는 평가만 한다. 실행 가능한 슬롯 수에 맞춰 순차 재사용해도 된다.

각 회차는 `runs/<run_id>/`에 근거·결과·상태를 보존한다. `state.json`은 입력 해시·단계·시도수·요청ID·출력경로·다음관측시각을 기록한다. 상위 입력 변경은 하위 리뷰 무효화, 같은 게시물 중복 전송 금지. 콘텐츠 성과와 워크플로우 변경 실험은 별도 기록한다. 소수 게시물 성과만으로 스킬을 자동 개정하지 않는다.

계정 로그인/권한 경계를 우회하지 않는다. API 키·쿠키·인증코드를 결과 파일에 넣지 않는다. 사용자 중지 요청은 즉시 우선한다. 완료 답변은 실제 만든 문서/영상/게시 URL과 남은 한계를 직접 링크한다.

## Harness² 개선 실험

사용자가 루프 개선을 요청하거나 반복 실패의 근거가 생기면 연구 메모의 Propose–Probe–Compose를 적용한다. 기본 기획/리뷰 실행과 절차 후보1개·도메인 후보1개를 고정된 원본·제품자료·모델·평가표에서 비교한다. 채택할 변경을 조합한 뒤 조합판도 재실행한다. 근거 없으면 기본판 유지. 각 개선 실행은 새 `runs/<run_id>/`와 그 아래 `artifacts/experiments/<id>/`에 분리하고 채택 이유와 실패를 남긴다. 개선용 병렬 탐색에 실제 영상 생성·반복 게시를 자동 포함하지 않는다. 회차 중 스킬 버전은 고정하며 다음 회차에서 필요한 교훈만 재사용한다.

## 회차 활성화

config의 모드는 새 회차의 기본값이다. 사용자가 제작/게시 실행을 명시한 경우 그 회차 `state.json.activation`에 mode, production_enabled, publishing_enabled, accounts, asset_ids, budget_usd, authorization_evidence를 저장해 그 회차에만 적용한다. 현재 유효한 사용자 중지 지시는 activation보다 우선한다. 명시 요청 없이 글로벌 기본값을 영구 활성화하지 않는다. 입력이 충분한 동일 승인 회차에서 반복 승인을 요청하지 않는다. 활성화 근거가 없는 설계 회차는 생성·게시하지 않는다.

## 고정 음성: dupy-female-v1

음성 설정의 기준은 `workflow/config.json`이 가리키는 `assets/voices/dupy-female-v1/profile.json`이다. 실제 선택본과 모델은 비공개 프로필을 기준으로 한다. OpenRouter에 프로필의 WAV·전사·연출 지시를 동일하게 보낸다. 전송 전 WAV SHA-256이 프로필과 일치하는지 확인한다. `input_references`에 오디오와 전사를 넣고 `voice` 필드는 생략한다. 이것은 로컬 프로필 ID이며 공급자가 발급한 voice ID가 아니다.

매번 같은 정리된 참고 WAV를 재사용한다. 프로필 변경 요청 없이 재처리하거나 생성 음성을 다시 클론 입력으로 쓰지 않는다. 다른 음성으로 임의 대체하지 않는다. WAV는 Git 제외 로컬 자산이므로 누락/해시 불일치 시 중지하고 복원한다. 새 대사만 바꾸며, 음성 기준 변경은 사용자 요청이 있을 때만 한다. 같은 참고 음성이라도 생성별 억양·잡음 차이가 생길 수 있으므로 끝어미·배경 잡음을 검수한다.

## 실행 기록과 부분 실행

매 호출에서 `workflow/run-records.md`의 단계 ID와 JSON 계약을 적용한다. `python3 scripts/run_artifacts.py start`로 KST 마이크로초+난수 run_id를 만들고 사용자 요청·selected_stages·scope·이전 실행 연결을 저장한다. 전체7단계가 기본으로 자동 실행되는 것은 아니다. 요청한 단계만 실행하고 선행 결과는 지정된 기존 자료/실행의 해시와 함께 재사용한다. 범위 밖 단계를 자동 추가하지 않는다.

각 단계/리뷰/재시도 후 `scripts/run_artifacts.py record`로 inputs, observations, decision_summary, revisions, conclusion, outputs, checks, status, error를 JSON 저장한다. 내부 사고과정 원문이 아니라 근거와 대안 선택 이유의 간결한 요약을 남긴다. 수정이 없으면 revisions는 빈 배열. 실패·중지·불명도 숨기지 않는다. 각 산출물은 해당 run/artifacts 안에 보존하고 고정 자산만 경로·해시로 참조한다. 과거 시도는 덮어쓰지 않는다.

새 사용자 요청의 재개는 새 실행 폴더로 연결하고, 같은 요청 안의 재시도는 동일 실행 아래 새 기록을 쓴다. 불필요한 단계는 skipped/completed로 위장하지 않는다. 필수 입력이 없으면 blocked로 기록한다. 음성만, 기획만, 리뷰만, 게시만, 개선만 실행할 수 있으며 각 범위에 필요한 입력만 요구한다. 게시만 요청해도 정확한 최종본·문안·계정의 검수 기록과 현재 사용자 선택은 확인한다. 미해결 항목을 알고 선택한 경우에는 `workflow/publishing.md`를 따른다. 종료 시 실행 폴더와 주요 JSON을 링크한다. 기록 생성 자체는 제작/게시 승인이 아니다.

## 직접 촬영한 영상 애셋

기획·제작에 실제 촬영물이 필요하면 config.asset_library와 `assets/source-videos/README.md`, catalog.json을 확인한다. 미등록 영상도 폴더에서 확인하고 실제 검토한 내용만 등록한다. 파일 추가 자체를 외부 업로드/생성 승인으로 보지 않는다. 원본 수정·이동·삭제 없이 사용하고, 파생본은 해당 run/artifacts에 저장한다. 단계 JSON inputs에 asset ID·경로·SHA-256·사용 구간을 남긴다. 요청 범위에 필요한 파일만 살펴본다.

## 레퍼런스 재현과 촬영본 편집

기획·제작·리뷰 전에 `workflow/reference-editing.md`를 읽는다. 화면 구성/순서, 컷 전환/길이, 자막 위치/크기/타이밍, 내용, 훅·CTA를 전체 원본의 타임코드별로 분석한다. 각 shot을 Dupy에1:1 치환하고 구조를 임의 창작하지 않는다. 기존 탐색용 요약만으로 이 분석을 완료 처리하지 않는다.

촬영본은 완성본이 아니다. 원본의 모든 오디오 트랙을 제거하고 필요한 구간만 잘라 레퍼런스의 장면 길이에 맞게 배속·홀드·크롭·자막·고정 내레이션을 조립한다. 입력/결과가 읽히도록 하고 실패·대기·화면 이탈을 제외한다. edit-timeline.json에 원본 구간·배속·출력 구간·무음화·자막을 저장한다. catalog의 preferred를 우선하고 _alternates는 자동 재수집하지 않는다.

기본 원칙은 **훅은 레퍼런스 그대로 유지하고, 설명부에서 Dupy 내용과 차별점을 보여준다**이다. 자막을 단순히 크게 만드는 데서 끝내지 않는다. 원본의 실제 글자 높이·위치·폰트 느낌과 굵기·테두리·색·하이라이팅·줄 수·문구 분할·등장/퇴장 박자를 측정하고 출력 해상도에 맞춰 재현한다. 원본에 강조색이나 배경 박스가 없으면 추가하지 않는다. 긴 문장 두 줄로 임의 합치거나 하단 안전영역 규칙으로 원본 위치를 대체하지 않는다. 폰트가 확인되지 않으면 유사 폰트와 차이를 기록한다.

원본에 없는 엔딩 카드·반복 문구·전환 효과·설명 장면을 임의로 만들지 않는다. 훅·데모·CTA의 화면 구성과 순서를 유지하며, 대사 길이/실제 제품 동작 때문에 필요한 차이는 타임코드와 이유를 남긴다. 리뷰에는 같은 화면 크기로 맞춘 원본/결과 비교 프레임을 포함하고 자막 bbox·실제 글자 높이·굵기·강조·박자가 맞는지 확인한다. 비교하지 못한 항목은 PASS로 처리하지 않는다.

촬영한 제품 화면의 원음 제거 규칙은 사용자가 채택한 AI 훅 영상의 네이티브 음성에는 적용하지 않는다. 기존 훅을 그대로 쓰라는 요청이면 그 영상과 음성을 함께 보존한다. 별도 요청 없이 재더빙·음성 덮어쓰기·립싱크 타이밍 변경을 하지 않는다.

## 최근 실행에서 검증한 편집·예약 기준

- 발화 전후 무음을 먼저 측정한다. 음성 길이·글자 수로 자막과 컷을 비례 배분하지 말고 실제 발화와 클릭·입력·결과 동작을 맞춘다. 멈춘 미리보기와 실제 결과 재생을 구분한다.
- 네이티브 음성 보존과 정밀 립싱크는 별개다. 배속은 지정 구간의 영상·음성·자막을 함께 바꾸고, 문구 수정은 해당 음성과 자막만 교체·재정렬한다. 부분 PASS로 이전 한계를 없애지 않는다.
- 성긴 프레임이나 자동 리뷰의 포괄적인 PASS는 정밀 립싱크 근거가 아니다. 전체 재생·전사·프레임·파일 검사를 구분해 기록한다. 상세 절차는 `workflow/reference-editing.md`를 따른다.
- 예약은 `workflow/publishing.md`를 읽고 현재 계정 이름·최신 파일 해시·절대 KST 날짜를 확인한다. 파일 대기 상태는 예약 완료가 아니며 업로드 후 예약을 재조회한다. 기존 예약 ID로 실패를 복구하고 게시·DM 수신 여부는 별도로 확인한다.
- 공개 문서에는 운영 규칙과 완료 범위만 반영한다. 레퍼런스 채널·상세 모델·개인 경로·생성 및 예약 영수증은 비공개 자료로 유지한다.
