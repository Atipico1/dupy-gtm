# Dupy GTM — Self-Improving Agent Harness

**실제 콘텐츠를 만들고 배포하면서, 실패한 판단과 제작 절차를 다음 실행의 개선 근거로 축적하는 GTM 하네스.**

Dupy의 쇼핑쇼츠 GTM을 리서치부터 기획·제작·검수·게시·성과 회수까지 연결한다. 사용자가 선택한 레퍼런스의 훅과 전개를 유지하고, 설명부는 실제 Dupy 데모로 바꾼다. 콘텐츠의 결과뿐 아니라 **어떤 입력과 규칙이 그 결과를 만들었는지**를 회차별로 남긴다.

현재까지 실제 콘텐츠 제작·수정·예약과 단계별 실행 기록을 운영했다. 이 경험을 바탕으로, 실패 재현과 비교 검증을 거쳐 실행 규칙을 갱신하는 자기개선 구조를 구체화했다. **후보 패치 생성부터 검증·자동 승격·복귀까지 연결하는 엔진은 다음 구현 범위다.**

## 운영 중 바꾼 것

발화형 AI 훅에서 얼굴 일관성과 립싱크 문제가 반복돼, 하네스가 무음 리액션과 자막으로 제작 방식을 전환했다. 제품 설명은 실제 Dupy 데모와 내레이션으로 이어갔고, 전환한 포맷의 게시물에서 좋은 반응을 확인했다. [전환 과정과 결과](research/hook-format-transition.md).

## 실행에서 학습으로

| 층 | 하는 일 | 현재 진척 |
|---|---|---|
| **GTM 실행** | 성과·시장 분석 → 기획 → 리뷰 → 제작 → 검수 → 게시 | 실제 제작·수정·예약 운영, 요청한 단계만 부분 실행 |
| **하네스 개선** | 실패 근거 → 원인 가설 → 절차 수정 → 비교 검증 → 다음 회차 적용 | 제작 전략 변경과 후속 반응 관측, 재현 평가·승격 절차 설계 |
| **개선기 개선** | 진단과 후보 선택 방식도 평가하고 더 나은 절차로 갱신 | 고정 평가 기준과 권한 경계를 포함한 설계 |

실행 규칙은 회차 안에서 고정한다. 개선 후보는 기존 성공 사례를 깨지 않는지 확인한 뒤 다음 회차에 반영하도록 설계했다. 검증되지 않은 제안과 실제 채택한 운영 규칙을 구분한다.

## 편집과 검수 개선

- **문장 길이에서 실제 발화로:** 자막·컷을 글자 수로 나누던 문제를 확인하고 음성·화면 동작에 맞춰 수정했다.
- **전체 재생성에서 부분 수정으로:** 훅·CTA·한 문장 수정의 범위를 분리하고, 변경 구간과 연결부를 검수하는 절차를 정리했다.
- **결과물에서 실행 근거까지:** 단계별 입력·관측·수정·결론·산출물을 JSON으로 남기고 파일 해시와 검수 결과를 연결한다.
- **학습 내용도 재검토:** 캡션을 실제 영상 훅으로 오인한 기존 가설을 철회했다. 다음 설계에는 원본 영상 근거와 반례를 통한 교훈 검증을 포함했다.

포맷 전환과 편집 개선은 실제 운영에서 수행한 변경이다. 고정 평가 세트에서 자동 패치를 비교·승격하는 검증 체계는 다음 단계다. [진척과 다음 검증](workflow/self-improving-harness.md) · [날짜별 작업 기록](docs/work-log/2026-11-01.md)

## 다음에 증명할 것

실패 사례를 재현하고 기존판과 수정판을 같은 입력에서 비교하는 평가·적용 경로를 구현한다.

대표 평가 대상은 화면·대사 불일치, 승인한 훅의 임의 변경, 잘린 발화, 근거 없는 검수 통과다. 실패 사례와 정상 사례를 함께 시험하고, 수정에 사용하지 않은 사례에서도 확인한다. 효과 없는 후보는 기각하고 회귀가 발생하면 이전 검증판으로 복귀하는 경로를 만든다.

연동은 Higgsfield, OpenRouter, TikHub를 사용하며 Harness 연구를 설계 근거로 삼는다. 상세 모델·레퍼런스 채널·운영 계정·개인 미디어는 비공개로 관리한다. 11월의 설계 보강은 최초 7일 운영 결과와 구분한다.

## 현재 상태와 실행

영상 후보 제작, 음성·자막·화면 동작의 타이밍 수정, 훅·CTA 구간 배속, 사용자 선택본의 예약 등록과 댓글 DM 규칙 연결까지 실행했다. [작업 현황](workflow/progress.md)은 완료한 작업과 남은 검증을 구분한다. 실제 영상·예약 영수증·검토 기록은 비공개 실행 폴더에 보관한다.

기본 설정은 계속 `design_only`, 제작·게시 비활성이다. 실행별 사용자 요청이 허용한 단계만 활성화하며, 저장소를 내려받거나 스킬을 설치하는 것만으로 생성·게시가 시작되지는 않는다. 연결된 예약 서비스의 실행기와 이 저장소의 스킬은 별개다.

- 제작·부분 수정: [레퍼런스와 편집 계약](workflow/reference-editing.md)
- 예약·업로드·댓글 DM 확인: [게시 계약](workflow/publishing.md)
- 단계별 입력·근거·수정·결과 기록: [실행 기록](workflow/run-records.md)

프로젝트 스킬은 `.agents/skills/`에서 버전 관리한다. 전역 설치본이 있다면 동일 운영 규칙을 반영하되 로컬 경로·공급자 설정을 공개 사본에 복사하지 않는다. 실제 호출에는 비공개 자산, 선택한 음성 프로필, 계정 연결과 공급자 자격증명이 필요하다.

## Git에 포함하는 것

공용 설계·스킬·레퍼런스 분석 문서와 보조 도구를 관리한다. 개인 애셋과 생성 작업 문서·요청 데이터는 비공개 폴더에 둔다. 영상·오디오·이미지, 엑셀/PDF/ZIP, 원시 API 응답과 작업 상태·영수증, 캐시·실행 기록은 `.gitignore`로 제외한다. 제외 파일은 로컬에 그대로 남는다.

따라서 새 clone에는 원본 영상이나 엑셀이 없고 로컬 검토 링크 일부가 열리지 않을 수 있다. 기존 원본 보관함을 별도로 복원하거나 명시적으로 다시 수집해야 한다. API 키·로그인 쿠키·인증 코드는 커밋하지 않는다.

## 고정 음성

[dupy-female-v1](assets/voices/dupy-female-v1/profile.json)은 사용자가 선택한 음성의 생성 조건이다. OpenRouter에 프로필의 참고 WAV·전사·연출 지시를 보내고 새 대사만 바꾼다. 공급자 voice ID가 아닌 로컬 프로필이다. WAV는 Git에서 제외되므로 다른 환경에서는 파일을 별도로 복원하고 SHA-256을 확인해야 한다. 생성된 결과 음성을 다시 참고 입력으로 쓰지 않는다.

## 부분 실행과 실행 기록

“기획만”, “음성만 생성”, “영상 리뷰만”, “루프 개선만”처럼 원하는 범위로 실행할 수 있다. 필요한 기존 산출물은 실행 ID/경로로 연결하며 요청하지 않은 단계를 자동으로 돌리지 않는다.

매 실행은 `runs/20261024T180000123456+0900-a1b2c3d4/` 형태의 고유 폴더를 만든다. `run.json`에는 요청/범위/설정 스냅샷을, `stages/`에는 입력·관측·판단 근거 요약·수정 전후·결론·검증·산출물 경로를 JSON으로 남긴다. 같은 요청의 재시도도 별도 기록으로 보존한다. 자세한 계약은 [실행 기록](workflow/run-records.md), 기록 도구는 [run_artifacts.py](scripts/run_artifacts.py)다. 이 도구는 실행 기록을 관리하며 API 작업을 자동 실행하지 않는다.

## 직접 촬영한 영상

[원본 보관함](assets/source-videos/README.md)에 영상을 넣는다. 날짜별 폴더도 사용할 수 있다. [목록](assets/source-videos/catalog.json)에는 설명·촬영일·용도·태그를 기록하며, 파일만 먼저 넣으면 이후 요청 때 등록할 수 있다. 원본은 보존하고 편집본은 실행별 artifacts 폴더에 저장한다. 영상은 Git 제외이며 자동 업로드/생성은 하지 않는다.

## 비공개 로컬 자료

`assets/`, `creative/`, `outputs/`, `runs/`는 폴더 전체를 Git에서 제외한다. 애셋 목록·음성 프로필도 로컬 자료이며 새 clone에 포함되지 않는다. 복원은 별도 비공개 보관본에서 한다. `.gitignore`는 Git 추적 방지이며 클라우드 공유 권한을 설정하거나 과거 커밋을 삭제하지는 않는다. 레퍼런스의 상세 재현/편집 규칙은 [편집 계약](workflow/reference-editing.md)에 있다.
