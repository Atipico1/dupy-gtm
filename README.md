# Dupy GTM

Dupy의 Instagram·Threads 콘텐츠 운영을 설계하고, 제품 근거와 레퍼런스 분석을 관리하는 저장소다. 검증된 레퍼런스의 훅·사용 장면·CTA를 Dupy에 맞게 변주한다.

## 워크플로우

1. 연결된 인앱 브라우저에서 내 콘텐츠 성과 분석
2. TikHub으로 지정 채널·시장 레퍼런스 분석
3. 훅·사용 장면·CTA 기획 후보 작성
4. 기획 리뷰 후 가장 좋은 1개 선정
5. 전용 인물·배경 사진, 원본 video reference, 음성 생성 모델 음성을 사용해 영상 생성 모델로 제작
6. 최종 영상·음성·게시 문안 전체 검수
7. 검수를 통과한 콘텐츠 게시 후 성과 회수

별도 개선 에이전트는 회차의 실행 기록과 후속 성과를 분석한다. Harness²의 Propose–Probe–Compose를 참고해 기존 절차와 수정안을 비교하고, 근거가 있는 변경만 다음 회차에 적용한다. 현재 회차의 규칙은 고정한다.

## 현재 상태와 실행

현재는 **설계 및 스킬 정의 완료** 상태다. 자동 실행기나 정기 스케줄은 가동하지 않았고, 기본 설정은 `design_only`, 제작·게시 비활성이다. 스킬 파일만으로 백그라운드 루프가 실행되지는 않는다.

실행 요청 시 스킬이 설정과 기존 회차를 먼저 읽는다. 전용 인물·배경 사진, 고정 음성 자산, 예산 및 실행 범위가 정해진 회차만 활성화한다. 승인된 회차에서는 리뷰 통과 후 게시까지 진행한다. 사용자 중지 지시가 최우선이며 응답이 불명확한 생성·게시 요청을 중복 전송하지 않는다.

프로젝트 스킬은 `.agents/skills/`에서 버전 관리한다. 사용자 전역 설치본이 있다면 이 사본과 별개이므로 변경 시 동기화한다. 현재 문서와 일부 보조 스크립트는 작성자의 절대 경로 및 기존 로컬 환경을 참조한다. 다른 컴퓨터에서는 프로젝트 경로·자격증명 환경을 확인해야 한다. 조사 스크립트는 유료 API 호출을 포함할 수 있으며 설정 파일이 모든 독립 스크립트를 자동 차단하는 것은 아니다.

## Git에 포함하는 것

공용 설계·스킬·레퍼런스 분석 문서와 보조 도구를 관리한다. 개인 애셋과 생성 작업 문서·요청 데이터는 비공개 폴더에 둔다. 영상·오디오·이미지, 엑셀/PDF/ZIP, 원시 API 응답과 작업 상태·영수증, 캐시·실행 기록은 `.gitignore`로 제외한다. 제외 파일은 로컬에 그대로 남는다.

따라서 새 clone에는 원본 영상이나 엑셀이 없고 로컬 검토 링크 일부가 열리지 않을 수 있다. 기존 원본 보관함을 별도로 복원하거나 명시적으로 다시 수집해야 한다. API 키·로그인 쿠키·인증 코드는 커밋하지 않는다.

## 고정 음성

[dupy-female-v1](assets/voices/dupy-female-v1/profile.json)은 사용자가 선택한 denoise 후 클론2번의 생성 조건이다. OpenRouter 음성 생성 모델에 같은 참고 WAV·전사·연출 지시를 매번 보내고 새 대사만 바꾼다. 공급자 voice ID가 아닌 로컬 프로필이다. WAV는 Git에서 제외되므로 다른 환경에서는 파일을 별도로 복원하고 SHA-256을 확인해야 한다. 생성된 결과 음성을 다시 참고 입력으로 쓰지 않는다.

## 부분 실행과 실행 기록

“기획만”, “음성만 생성”, “영상 리뷰만”, “루프 개선만”처럼 원하는 범위로 실행할 수 있다. 필요한 기존 산출물은 실행 ID/경로로 연결하며 요청하지 않은 단계를 자동으로 돌리지 않는다.

매 실행은 `runs/20261024T180000123456+0900-a1b2c3d4/` 형태의 고유 폴더를 만든다. `run.json`에는 요청/범위/설정 스냅샷을, `stages/`에는 입력·관측·판단 근거 요약·수정 전후·결론·검증·산출물 경로를 JSON으로 남긴다. 같은 요청의 재시도도 별도 기록으로 보존한다. 자세한 계약은 [실행 기록](workflow/run-records.md), 기록 도구는 [run_artifacts.py](scripts/run_artifacts.py)다. 이 도구는 실행 기록을 관리하며 API 작업을 자동 실행하지 않는다.

## 직접 촬영한 영상

[원본 보관함](assets/source-videos/README.md)에 영상을 넣는다. 날짜별 폴더도 사용할 수 있다. [목록](assets/source-videos/catalog.json)에는 설명·촬영일·용도·태그를 기록하며, 파일만 먼저 넣으면 이후 요청 때 등록할 수 있다. 원본은 보존하고 편집본은 실행별 artifacts 폴더에 저장한다. 영상은 Git 제외이며 자동 업로드/생성은 하지 않는다.

## 비공개 로컬 자료

`assets/`, `creative/`, `outputs/`, `runs/`는 폴더 전체를 Git에서 제외한다. 애셋 목록·음성 프로필도 로컬 자료이며 새 clone에 포함되지 않는다. 복원은 별도 비공개 보관본에서 한다. `.gitignore`는 Git 추적 방지이며 클라우드 공유 권한을 설정하거나 과거 커밋을 삭제하지는 않는다. 레퍼런스의 상세 재현/편집 규칙은 [편집 계약](workflow/reference-editing.md)에 있다.
